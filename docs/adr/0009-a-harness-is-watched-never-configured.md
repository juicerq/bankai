# A harness is watched, never configured

ADR-0008 let a Harness install a hook so a card could reach Working, Done and needs-attention sooner than `ACTIVITY_POLL_MS`. We reverse that: a Harness declares the files it already writes and Bankai watches them, so nothing is written into a harness's configuration. Claude rewrites `~/.claude/sessions/<pid>.json` on every card-level status edge, and Codex appends its turn edges to the root rollout, both within a fraction of a second — watching those files buys the same latency the hook bought. On startup Bankai removes the hook entries, scripts and spool it previously installed.

The hook cost a generated shell script running on every tool call, a spool directory with its own pruning, a settings toggle, a store migrator and a per-harness install path — all to shorten a delay that reading two files already shortens. What the hook alone could give is the text of the question a harness stopped on: `needs-attention` keeps coming from the registry's `waiting` status, but the phone's attention card and the push notification now say the state and nothing more. We accept that loss. ADR-0001's reasoning stands again in full: Bankai observes what a harness already exposes and degrades to the poll, never to a broken configuration.
