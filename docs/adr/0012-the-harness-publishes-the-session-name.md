# The harness publishes the session name

Supersedes ADR-0008. That decision rested on a premise that has expired: Claude Code published no name for its own conversation, so bankai paid for one — `claude -p --model haiku` per shell at turn milestones 3, 10, 30 and 100, measured at 7.2s and 304 MB of transient RSS per call. Claude Code now writes `{"type":"ai-title","aiTitle":...}` into the very transcript bankai already reads, and it is the name its own `/resume` list shows. Bankai reads that name instead of generating one.

Across the 60 most recent transcripts on the author's machine, 56 carry an `ai-title` or `custom-title`. The first title appears at record 15 in the median session and as late as record 719, after Bankai has already observed the turn start. Codex exposes the same title its resume list shows through `thread/read`: an explicit `name` when the user renamed it, otherwise the extracted `preview`. The response also carries the exact transcript path, so Bankai does not scan Codex's storage. Both harnesses answer through one seam, `Harness.title`.

## What was rejected

**Keeping any fallback name.** A model call would recreate the system this decision removes, while the first user message is a prompt rather than the name shown by the agent CLI. Until the harness publishes a name the card uses its ordinary branch fallback.

**Scanning the transcript forward for the name.** The first Claude `ai-title` sits up to 1 MB into a resumed transcript, because the resume appends after the whole prior conversation. The last one is never more than 33 KB from the end across those same 60 files, so the reader takes a 128 KB tail and walks it backwards. Cost is constant in session size, against a p99 transcript of 13 MB. Codex needs no transcript scan because its app server returns the native title.

**Keeping the naming milestones.** They existed to ration a 7.2s paid call. Reading the native source is cheap and idempotent. Bankai reads once when it binds the live Agent session, watches its transcript, and reads again when the source changes or a turn changes state. That covers the first generated name and a restart with an existing session without polling every transcript continuously.

**Keeping the per-harness naming toggle.** It let the user decline a call that cost money and time. Declining to read a field the CLI already wrote buys nothing. The toggle is gone; renaming by hand is still final.

## Consequences

- Store v10 drops names generated by Bankai and old first-message names from Agent sessions, migrates native published names to `titleSource: "harness"`, and drops `namings`, the milestone counter.
- A resumed session takes the name of the conversation it resumed into, rather than keeping the one the shell carried. ADR-0008 wanted this and approximated it with a three-turn delay; it is now exact.
- A Codex session uses its explicit name when present and otherwise the extracted title shown by `codex resume`. Claude uses its latest published title.
- The naming subsystem is gone: `session-namer.ts`, `naming-slots.ts`, `name-contract.ts`, both namers, and `transcript-material.ts` — about 450 lines, replaced by two file reads.
