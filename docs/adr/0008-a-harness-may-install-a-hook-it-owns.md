# A harness may install a hook Bankai owns end to end

ADR-0001 chose passive Agent detection because hooks mutate configuration Bankai does not own. Passive discovery and `/proc` binding remain the authority for session identity and Working/Done, but the poll is up to `ACTIVITY_POLL_MS` behind the two edges a user acts on: the turn ending, and the harness stopping to ask a question. A Harness may therefore install a hook when it merges and removes only Bankai's own entries, preserves every user hook, keeps the hook file-only and non-blocking, and degrades to the poll when the hook is absent, untrusted, or unparseable.

The hook reports facts about the session's state, never a running commentary on it. Bankai read tool events for a while and rendered them as a per-tool label on the card; the label was correct and nobody wanted it, and it cost a dwell queue, a compaction scraper, a PTY line scraper and a per-tool vocabulary per harness. A card says Working, Done, or needs attention, and the hook exists to move it between those three sooner. This supersedes only ADR-0001's blanket ban on hooks; it does not make hooks the authority for Agent presence or Continuity.
