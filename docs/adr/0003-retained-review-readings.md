# Retained Review readings, anchored by line

The Review reads a Project's changes while an Agent is writing to that Project, so its content is replaced constantly and never at a moment the user chose. Until now a replacement whose changed-file set differed published a snapshot without content — the Review-level loading state over the whole diff — and remounted the diff surface, sending the Reading position back to the top. Both were inherited, not chosen: the reading refactor that produced the current hook listed the scroll reset under "any visible behavior change" it deliberately preserved, and pinned it in a test. We decided instead that the Review retains the last complete reading — snapshot, content, Tree, and totals together — until its replacement is complete, and re-anchors the Reading position by line across the replacement. The cost is that the Review can show content a second or two old during a burst of writes, with only a delayed passive indicator to say so; we prefer stale-but-readable over a diff that blanks and jumps while it is being read. Atomic presentation is kept rather than relaxed into per-file placeholders, which the project already tried and reverted.

## Consequences

- Retention is keyed by Project and Scope, so an update the user did not ask for costs nothing, while a Scope switch still shows a loading state and starts at the top. The distinction is the user's intent, not the size of the change.
- Under continuous writes a replacement can be invalidated before it completes, so the retention window stretches and the Review lags rather than flickers. Relaying the watcher's changed filenames so unchanged files are reused instead of re-read is the follow-up that shortens it; it changes the main and preload contracts, which is why it is not part of this decision.
- The Reading position lives above the rows it points into: the diff surface still remounts per layout, and the position it mounts at is data its caller holds. A replacement therefore paints once, at the line the user was on, instead of painting at the top and correcting itself afterwards. Scope owns the caller's lifecycle, as it already does for the Tree, so switching Scope starts fresh.
- Anchoring is by changed line, so the position is stable when content shifts above it, at the cost of snapping to the start of that line's row. Restoring the position depends on every row kind having a fixed height; a measured row would make the offset a guess.
